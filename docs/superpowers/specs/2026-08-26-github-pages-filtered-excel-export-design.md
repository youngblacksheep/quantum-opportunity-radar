# GitHub Pages 当前筛选结果 Excel 导出设计

日期：2026-08-26

## 目标

在 GitHub Pages 静态首页的“申报机会”区域增加“导出当前筛选结果”按钮。用户按关键词、阶段、层级、省份和主题筛选后，按钮只导出当前页面对应的机会集合。

## 方案

采用浏览器端、无第三方依赖的 Excel 兼容 `.xls` 导出。下载内容是带 UTF-8 BOM 的 HTML 表格 Blob，使用 Excel MIME 类型和 `.xls` 扩展名；Excel 与 WPS 可直接打开，避免依赖 CDN 或运行时访问外部服务。

不采用 CSV，因为 CSV 无法稳定保存表头样式、中文链接和多字段可读性；不引入 SheetJS，因为静态站在网络受限环境下不应依赖第三方脚本才能导出。

## 导出字段与口径

导出列固定为：课题名称、层级、地区、主管单位、发布时间、申报开始时间、截止时间、阶段、主题标签、申请要求、区域要求、资金信息、官方来源、数据核验时间。

阶段使用页面已有的 `effectiveStage()` 结果，而不是直接信任原始 `stage`，保证已过期项目不会在导出表中继续显示为“正在申报”。官方来源列使用可点击的完整 URL。

文件名格式为 `量子信息与安全课题机会_当前筛选_YYYY-MM-DD.xls`。导出前根据当前控件值生成筛选描述；文件名中的路径分隔符、控制字符和过长文本会被清理。

## 交互与错误处理

- 按钮位于筛选控件和结果计数附近，与现有视觉风格一致，并有明确的 `aria-label`。
- 按钮文本为“导出当前筛选结果”；导出过程中短暂显示“正在导出…”，避免重复触发。
- 当前筛选没有结果时，不创建下载文件，仅提示“当前筛选没有可导出的课题”。
- 浏览器不支持 Blob/下载 API 时，显示可读错误提示，不影响页面筛选和浏览。
- 导出不请求网络、不写入后端、不改变页面状态；它只读取已经加载到 `state.opportunities` 的数据。

## 测试与验收

测试先覆盖纯函数：当前筛选结果映射为固定列顺序、HTML 单元格正确转义、有效阶段使用 `effectiveStage()`、空结果不下载、文件名清理稳定。再做静态页面验收：按钮存在、桌面与手机宽度不溢出、点击后产生 `.xls` 下载、导出行数等于结果计数。

## 非目标

本次不改 Cloudflare Worker、D1、数据来源、筛选规则或 GitHub Actions；不导出已获批团队和来源覆盖统计；不新增 Excel 第三方运行时依赖。
